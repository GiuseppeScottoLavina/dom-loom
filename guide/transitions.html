DomLoom guide

Transitions

stage.transition(update) works like document.startViewTransition(update), drawn by the compositor: it keeps a picture of the old content, runs your update, then cuts to the new content. Unlike a native view transition, the new content is live while it plays: a click on a flying element reaches that element, and the old picture takes no input.

A cut between two views

Put the change inside the callback. The blade runs across the stage; ahead of it the old page breaks into blocks that are blown away. Elements with the same data-morph value (or CSS view-transition-name) in both views fly on an arc from the old place to the new one, leave a streak, and reassemble. Each key should appear once in each visible view. The promise resolves when the transition has ended.

Press Ready: the title and the button fly to their new places. Change class runs the blade the other way.

direction: -1 runs the blade from right to left. With reduced motion, or without WebGPU, the same call swaps the content at once: the callback always runs.

A cut in one region

{ scope: element } cuts only the region of that element (or of a list of elements), measured before and after the update. The rest of the stage stays still. A scoped cut does not match data-morph keys.

Press Next and Previous: only the entry is cut, the way you move.

Elements that move

For a reorder or a move, pass the elements that move as morph, captured before the update, and cut: false for no blade. They fly from where they were to where they are after the update; those that are no longer shown crumble where they were. Keep each element's identity across the update (move the nodes, do not rebuild them).

Shuffle a few times quickly.

Page turn and melt

{ style: 'curl' } swaps the blade for a page turn: the old page peels away from one side, over the new one, which is live underneath; direction: -1 peels from the right. { style: 'melt' } drips the old page down and reveals the new one from the top. Both work for the whole stage or with scope. They come with dom-loom, or with the entries dom-loom/curl and dom-loom/melt; without them the name is unknown and the blade is used.

Turn the page, then melt it. During the turn, the new page is already live.

A page stage for an app's views

<loom-stage page> wraps an app's main view, whatever its height. At rest it is plain HTML: no canvas, no skin, and no cost when the view changes with the user's input; the stages inside it work as usual. transition() draws only the visible part of the view for the time of the cut: the stages inside are in the picture as they are, the data-morph elements visible in both views fly, the new view takes clicks during the cut, and the page gets its HTML back where the new view was shown.

Go from Lab to Stock: the page turns, and the title flies to its new place.

Remove and add with motion

await stage.discard(element) removes an element with motion: it crumbles where it was, and what comes after it flies into the space it leaves. { exit: 'shatter' } breaks it into shards instead (dom-loom/shatter). A framework passes its own update as the second argument, which removes the element from its state: stage.discard(element, update, { exit }). stage.reveal(element) has an element you just added assemble block by block.

Abandon one, shatter one, then add a few.

The same exit works in a transition: stage.transition(update, { morph: elements, exit: 'shatter' }) breaks the elements of morph that the update removes.

Options

OptionEffect
scopeAn element or a list of them: only their region is cut.
direction1 (the default) runs the cut left to right, -1 right to left.
morphThe elements that fly from where they were to where they are; with it, the rest of the stage's keys are ignored.
cutfalse for no blade: only the elements of morph fly.
style'curl' or 'melt', drawn in place of the blade.
exit'shatter': the elements of morph that the update removes break into shards instead of crumbling.
